1. Введение и архитектура

AnsibleOps — десктопный центр управления Ansible: запуск playbook, ad-hoc команды, визуальный конструктор, граф задач, админ-модули, домен, профили конфигураций, workflow-сценарии, центр операций с уровнями риска, compliance (Audit/Enforce), event-правила, diff и версии файлов, каталог ролей, планировщик, отчёты, локальный RPM-репозиторий, Git, Vault, Zabbix и Web API.

1.1 Архитектура

СлойТехнологияНазначение
ФронтендRust + egui/eframe 0.29Вкладки, граф, редактор, темы
БэкендRust + tokioАсинхронный запуск ansible/terraform, стриминг вывода, история (JSON)
ИнтеграцииAnsible Core, Terraform, Git, createrepo, Zabbix senderВызов системных CLI-команд через адаптеры
Принцип адаптеров: GUI не зашивает команды жёстко — операции описаны в каталогах (модуль ops.rs), поэтому добавление новых действий не требует переписывания интерфейса.

2. Установка и первый запуск

2.1 Windows

  1. Скопируйте ansibleops.exe в любую папку (например, C:\ansibleops).
  2. Установите Ansible (WSL) или укажите путь к прокси-скриптам ansible.cmd/ansible-playbook.cmd в PATH.
  3. Запустите ansibleops.exe двойным кликом.

2.2 РЕДОС (RPM)

sudo dnf install ./ansibleops-studio-1.2.0-1.*.rpm
ansibleops-studio

При отсутствии GUI-библиотек: sudo dnf install libX11 libxcb mesa-libGL fontconfig.

2.3 Первый запуск

  1. Откройте приложение — появится главное окно (рис. 3.1).
  2. В статус-баре слева проверьте строку версии ansible. Если «ansible: not installed» — см. главу 24.
  3. Нажмите 🎨 Cosmic в шапке, чтобы просмотреть 4 темы.

5. Вкладка «Run» — запуск playbook

  1. Inventory: введите путь или нажмите 📂 и выберите файл (inventory.ini).
  2. Playbook: аналогично выберите .yml.
  3. Extra vars (-e): при необходимости строка переменных, например env=prod.
  4. Нажмите 📥 Load inv — слева внизу появится список хостов с группами и адресами.
  5. Нажмите 📝 Load pb — playbook будет разобран (нужно для вкладки Graph).
  6. Блок SSH / Vault: укажите приватный ключ (📂), включите Use become (sudo), при необходимости Ask vault password, задайте forks (параллельность).
  7. Нажмите зелёную кнопку ▶ Run Playbook (или Ctrl+R).
  8. Следите за логом справа: строки ✓ [host] — ok, ↻ — changed, ✗ — failed, ⊘ — skipped. Счётчики-бейджи обновляются на лету.
  9. Auto-scroll — автопрокрутка; 🧹 Clear — очистка лога.
После завершения запись автоматически появляется во вкладке «History».
Кнопка запуска блокируется («⏳ Running...»), пока идёт выполнение.

6. Вкладка «Editor»

  1. Файл попадает в редактор после «📝 Load pb», «📋 Копировать в Editor» (Library/Roles) или генерации из Constructor/Profiles.
  2. Редактируйте YAML в большом поле (моноширинный шрифт).
  3. 💾 Save или Ctrl+S — сохранение на диск.
Путь открытого файла отображается рядом с заголовком.

8. Вкладка «Admin»

  1. Целевые хосты: группа или all.
  2. Модуль: Package / Service / User / File — под полем появится подсказка с допустимыми действиями и примерами имён.
  3. Действие (install, started, present…), Имя (nginx, sshd…), Доп. аргументы.
  4. Флаги: become (sudo), check mode (dry-run без изменений).
  5. ▶ Выполнить задачу — справа появится карточка задачи с прогресс-баром и выводом (раскройте «📋 Вывод»).

9. Вкладка «Ad-Hoc»

  1. Хосты, Модуль (ping/shell/dnf/service…), Аргументы.
  2. ▶ Выполнить — команда вида ansible all -m ping появится в выводе ниже.
  3. «📚 Справочник модулей» — раскрывающиеся карточки с параметрами.
Ad-Hoc — разовые операции без playbook: проверить связь, перезапустить сервис, поставить пакет.

10. Вкладка «Library»

  1. Выберите карточку готового решения.
  2. 📋 Копировать в Editor — YAML откроется в редакторе для правки.
  3. ▶ Deploy — быстрый запуск на хостах.

12. Вкладка «Diff» — изменения и версии файлов

  1. Раскройте «▶ Запустить dry-run текущего playbook» → 🔍 Запустить diff-сканирование. Выполнится ansible-playbook --check --diff; ниже появятся карточки: хост, файл, +N/−N строк; раскройте «Diff» для просмотра «до/после».
  2. «📑 История версий»: введите Хост и Файл (например, /etc/ssh/sshd_config).
  3. ⬇ Скачать и сохранить — файл скачивается с хоста (модуль slurp) и сохраняется как версия с датой.
  4. 🔄 Показать — список сохранённых версий; раскройте «Содержимое» для просмотра.
Рекомендуемый порядок работы с критичными конфигами: скачать версию → применить роль → при проблеме сравнить и восстановить вручную из сохранённой версии.

13. Вкладка «Graph»

  1. Предварительно нажмите «📝 Load pb» во вкладке Run.
  2. Узлы — задачи playbook; перетаскивайте их мышью для изменения порядка.
  3. При изменении появится «⚠️ Порядок изменён» → 💾 Сохранить в playbook перезапишет файл в новом порядке.

14. Вкладка «Terraform»

  1. Укажите Working directory (папка с .tf-файлами) через 📂.
  2. Auto-approve — без интерактивного подтверждения (для apply).
  3. Кнопки: 🔧 init → 📋 plan → ▶ apply; 💣 destroy — уничтожение инфраструктуры (осторожно!).
  4. Вывод streamed справа; ошибки подсвечены красным.

15. Вкладка «Tools» — инструменты

15.1 🩺 Диагностика

  1. Задайте порт (по умолчанию 80) и нажмите ▶ Проверить все хосты.
  2. Inventory загрузится автоматически; проверка идёт в фоне: ping, SSH:22, ваш порт.
  3. Результат: зелёные/красные индикаторы по каждому хосту.

15.2 🔐 Ansible Vault

  1. 📂 — выберите YAML с секретами; в соседнем поле — путь к файлу пароля (или пусто для запроса).
  2. 🔒 Encrypt — файл шифруется (начинается с $ANSIBLE_VAULT;); 🔓 Decrypt — расшифровка.

15.3 📦 Локальный RPM-репозиторий

  1. 📂 — папка с .rpm; список пакетов появится сразу.
  2. 🛠 createrepo — создаёт repodata; после этого репо можно раздавать по сети (baseurl=http://…).

15.4 🔗 Git

📂 — папка плейбуков; 📊 status, 📜 log, комментарий + 💾 commit all (add -A + commit).

15.5 🕐 Планировщик

➕ Добавить текущий playbook → задайте интервал (мин). Пока приложение открыто, запуск выполняется автоматически.

15.6 🤖 Zabbix

Server/Port → 📡 Отправить тестовую метрику (протокол sender). Ответ сервера выводится ниже.

15.7 📡 REST API

🌐 Запустить Web API (порт 8080) → в браузере http://localhost:8080 — статус, /api/history — JSON истории.

15.8 📄 Экспорт отчёта

Формат HTML/JSON/CSV → 📄 Экспортировать… → диалог выбора места и имени файла.

16. Вкладка «Domain»

  1. Хосты-контроллеры домена: хост с FreeIPA/Samba/realm.
  2. Выберите Операцию из списка (просмотр пользователей/групп/машин, создать пользователя, массовое отключение/включение учёток, сброс пароля, снятие блокировки, ввод/вывод из домена, lastlog, группы компьютерам, действия OU).
  3. Заполните Имя и Доп. (для массовых операций имена через пробел).
  4. ▶ Выполнить — вывод в журнале внизу.
Операции описаны адаптерами (ipa/wbinfo/realm/net) — на standalone-хостах часть команд вернёт «не в домене», это нормально.

17. Вкладка «Profiles»

  1. Выберите профиль: Базовая РС, Сервер приложений, Файловый сервер, АРМ администратора, Безопасный, Разработчика, Терминальный.
  2. Просмотрите состав: пакеты, службы, hardening.
  3. 📋 В Editor — правка YAML; 💾 Сохранить YAML; ▶ Deploy (push) — немедленное применение на хостах из вкладки Run.

19. Вкладка «OpsCenter» — центр операций

  1. Задайте Хосты и Параметр (имя службы/пользователя/команда для операций с {p}).
  2. Нажмите ▶ у операции. Уровни риска: 🟢 безопасная — выполняется сразу; 🟡 — окно подтверждения; 🔴 опасная — окно с обязательной причиной.
  3. Вывод — в «📜 Консоль» внизу.
«Перезагрузка хоста» и «Произвольная команда» — уровень 🔴. Используйте только после dry-run и согласования.

20. Вкладка «Compliance» — Audit/Enforce

  1. Хосты; ➕ Проверка: тип (service / package / port / file) + имя.
  2. ▶ Запустить — режим Audit: таблица «ожидалось / факт», ✓ или ✗.
  3. Включите Enforce (автоисправление) — отклонения исправляются автоматически (статус «исправлено»): служба поднимется, пакет установится, порт откроется в firewall.
Лучшая практика: сначала прогон в Audit, анализ отклонений, затем Enforce.

21. Вкладка «History»

Список всех запусков: статус-иконка, playbook, время начала/окончания, бейджи ok/chg/fail. 🔄 Refresh — обновить; 🗑 у записи — удалить; 🗑️ Очистить всё — полная очистка.

22. Отчёты и Web API

22.1 Экспорт отчёта последнего запуска

  1. Tools → «📄 Экспорт отчёта» → формат: HTML (красивая таблица для браузера), JSON (машины/интеграции), CSV (Excel/LibreOffice).
  2. 📄 Экспортировать… → выберите папку и имя → тост «📄 Сохранено: …».

22.2 Web API

Tools → «📡 REST API» → 🌐 Запустить. Эндпоинты: / — статусная страница; /api/history — JSON. Используйте для мониторинга с другого устройства.

23. Упаковка и развёртывание на РЕДОС

  1. В WSL: ./packaging/build_redos.sh — статическая сборка (musl) + RPM.
  2. Готовый RPM: packaging/rpmbuild/RPMS/x86_64/ansibleops-studio-1.2.0-1.*.rpm.
  3. Установка: sudo dnf install ./ansibleops-studio-*.rpm; запуск ansibleops-studio или из меню.
  4. Массовая раскатка: положите RPM в папку → Tools → 📦 → createrepo → раздайте по сети → на хостах playbook добавляет репо и ставит пакет (см. пример в главе 15.3).
